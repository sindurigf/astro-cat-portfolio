# Security

Report a vulnerability privately, not in a public issue:

1. GitHub private vulnerability reporting on this repository: "Report a
   vulnerability" on the Security tab.
2. Email the template's maintainer at <lol@sinduri.lol>.

In a fork, replace both contacts with your own before publishing: turn on
private vulnerability reporting under Settings > Code security, and name your
own address in place of the maintainer's.

- A deployed site publishes the address in `person.email` in
  `src/site.config.ts`, currently <hello@example.com>, in
  `/.well-known/security.txt`, with what the site runs. It is generated by
  `src/pages/.well-known/security.txt.ts`.
- `tests/security-txt.spec.ts` fails when this file stops naming the
  configured address, or when `security.txt`'s `Expires` date nears.
- Accessibility barriers are not security reports:
  [ACCESSIBILITY.md](ACCESSIBILITY.md#8-reporting-a-barrier).
